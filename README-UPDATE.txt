==============================
1. Dashboard กลายเป็น Trip Control Center
==============================
- Dashboard อยู่ปุ่มกลางเหมือนเดิม แต่เปลี่ยนจากหน้าสรุปทั่วไปเป็นศูนย์ควบคุมทริป
- ก่อนทริป: โฟกัสวันแรกของทริป
- ระหว่างทริป: โฟกัสวันนี้
- หลังทริป: โฟกัสวันสุดท้าย
- เห็นทันที:
  • จุดถัดไป / จำนวนจุดของวัน
  • จำนวนรายการที่ต้องจอง
  • ตั๋วที่แนบไว้
  • วิธีเดินทางที่บันทึกแล้ว / ยังขาด
  • งบประมาณเทียบรายจ่ายจริง
  • ความสดของข้อมูลสถานที่/ร้านอาหาร
  • ร้านอาหารใกล้แผนของวัน
  • Plan B ของวัน

==============================
2. ศูนย์การจอง (Reservation Hub)
==============================
- รวมรายการ “ต้องจอง” ไว้หน้าเดียว
- แยกจำนวน:
  • ต้องจอง
  • จองแล้ว
  • มีตั๋วแนบ
- ถ้าร้านอาหารในฐานข้อมูลมีข้อความว่าควรจอง แต่รายการในแผนยังเป็น “ใส่แผนแล้ว” ระบบจะแยกเป็น “ระบบแนะนำให้เช็กการจอง”
- ร้านที่มี bookingURL จะมีปุ่มไปหน้าจอง
- กดแก้สถานะรายการจาก Hub ได้
- สถานะยังเป็นข้อมูลที่ผู้ใช้บันทึกเอง แอปไม่ได้ยืนยันกับร้าน/ผู้ให้บริการอัตโนมัติ

แก้บัคจาก v1.2.0:
- ร้านที่ระบบประเมินว่าแนะนำให้จอง เดิมใช้ค่าภายใน “needs-booking” ซึ่งไม่ตรงกับสถานะ “need” ของแผน
- v1.3.0 แก้ให้รายการใหม่ใช้ “ต้องจอง” ถูกต้อง และ migrate ค่ารุ่นเก่าอัตโนมัติ

==============================
3. Route Hub — จัดเส้นทางทีละช่วง
==============================
- ใน Dashboard เห็น “บันทึกวิธีเดินทางแล้ว X/Y ช่วง”
- เปิด Route Hub แล้วเห็นเป็นคู่:
  จุด A → จุด B
- แต่ละช่วงมี:
  • Google Maps Transit
  • บันทึกวิธีเดินทางสำหรับอ่านออฟไลน์
  • แสดงข้อความที่บันทึกไว้แล้ว
- ใช้กับปุ่ม “จากจุดนี้ไปจุดถัดไป” เดิม
- ถ้าสลับลำดับแผน ระบบยังคงล้าง route note ที่อาจไม่ตรงกับลำดับใหม่ตามระบบเดิม

==============================
4. ร้านอาหารใกล้แผนวันนี้
==============================
- Dashboard อ่านสถานที่ในแผนที่มาจาก Discover แล้วจับ “ย่าน/เมือง”
- แนะนำร้านอาหารจากฐานข้อมูลในย่านเดียวกันก่อน
- ถ้าย่านเดียวกันไม่พอ จะคัดร้านในเมืองเดียวกัน
- แต่ละการ์ดแสดง:
  • ชื่อร้าน
  • ย่าน
  • เมนูเด่น/คำอธิบาย
  • งบ JPY + THB
  • วันที่/สถานะความสดของข้อมูล
  • ปุ่มรายละเอียด
  • Google Maps
- ไม่แนะนำร้านที่ถูกเพิ่มลงวันนั้นอยู่แล้ว

==============================
5. Data Freshness / Safety Check
==============================
Dashboard และ Hub อ่าน checkedAt จาก Discover แล้วแบ่ง:
- ใหม่: ตรวจข้อมูลไม่นาน
- ควรเช็กซ้ำ: ข้อมูลเริ่มเก่า
- ข้อมูลเก่า: เกินช่วงที่ตั้งไว้/ไม่มีวันที่ตรวจ

สำคัญ:
- เป็นการวัด “วันที่ฐานข้อมูลถูกตรวจ” ไม่ใช่สถานะเปิด/ปิดสด
- รายการสำคัญควรกด Official / Google Maps อีกครั้งก่อนออกเดินทาง
- ร้านอาหาร v1.2.0 ยังมี operationalStatus, warningNote, reservationNote และแหล่งข้อมูลเดิมครบ

==============================
6. Budget Planner แบบวางแผนก่อนใช้เงินจริง
==============================
เพิ่มปุ่ม “วางงบก่อนเที่ยว” ใน Dashboard
แยกงบเป็น:
- เครื่องบิน
- ที่พัก
- เดินทาง
- อาหาร
- ที่เที่ยว / ตั๋ว
- ช้อปปิ้ง
- เงินสำรอง

Dashboard เทียบ:
แผนทั้งหมด vs รายจ่ายจริงส่วนของฉัน
และแสดงจำนวนเงินเหลือ/เกินแผน

หมายเหตุ:
- Budget Planner เป็นแผน ไม่สร้างรายการรายจ่ายให้อัตโนมัติ
- ถ้ายังไม่ได้ตั้งงบรวม และกรอก Budget Planner ครั้งแรก ระบบนำยอดแผนรวมไปเป็นงบหลักให้

==============================
7. Plan B รายวัน
==============================
ใน Dashboard และหน้าแผนมี Plan B แยกตามวัน:
- ถ้าฝนตก
- ถ้าเหนื่อย / อยากลดแผน
- ถ้ามีเวลาเหลือ

ข้อความถูกเก็บในข้อมูลทริปและอ่านออฟไลน์ได้

==============================
8. Day Control Strip ในหน้าแผนเที่ยว
==============================
เหนือแผนของแต่ละวันเพิ่มปุ่มสรุป 4 ช่อง:
- เส้นทาง X/Y
- ต้องจองวันนี้
- ข้อมูลควรเช็ก
- Plan B
กดแล้วเปิด Hub ของวันนั้นได้ทันที ไม่ต้องย้อนกลับ Dashboard

==============================
9. Discover API ภายในสำหรับ Dashboard
==============================
Discover เพิ่ม helper ภายในเว็บสำหรับ:
- อ่าน metadata ของสถานที่/ร้านจาก discoverId
- แนะนำร้านอาหารจากย่านใน itinerary
- ตรวจ freshness ของรายการที่กำลังใช้ในแผน
- อ่านจำนวน Catalog
ไม่เพิ่ม API key และไม่ส่งข้อมูลทริปออกไป server

Catalog ปัจจุบัน:
- สถานที่ 60 แห่ง
- ร้านอาหาร 31 ร้าน
- Route 13 ชุด

==============================
ความเข้ากันได้
==============================
- localStorage key ยังเป็น tabi-v1 เดิม
- ทริป/รายจ่าย/ตั๋ว/Wishlist เดิมไม่ถูกล้าง
- ฟิลด์ใหม่ budgetPlan และ dayAlternatives เป็น optional ข้อมูลเก่าจึงเปิดได้
- Service Worker เปลี่ยน cache เป็น ichi-1.3.0
- core files ใช้ ?v=130
- ระบบรูป Universal Photo Resolver และ Restaurant Safety ของ v1.2.0 ยังอยู่ครบ

ผลตรวจโครงสร้าง
- JavaScript syntax ผ่าน app.js / discover.js
- 60 สถานที่
- 31 ร้านอาหาร
- 13 Routes
- ไม่มี ID สถานที่/ร้านซ้ำ
- ไม่มี Route ชี้ไป ID ที่ไม่มีอยู่
- ทุกสถานที่มี image / photoQuery / mapQuery สำหรับ Universal Photo Resolver
- ร้านอาหารทุกตัวมี checkedAt, sourceURL, reservationLabel และ operationalStatus

หมายเหตุการทดสอบ
- ควรทดสอบบนมือถือจริงหลัง Deploy อีกครั้ง โดยเฉพาะ Dashboard, Reservation Hub, Route Hub และการอัปเกรด Service Worker
- รูป/Google Maps/เว็บร้าน/ระบบจองต้องใช้อินเทอร์เน็ต ส่วนแผน, route note, Plan B, budget และตั๋วที่เก็บในเครื่องใช้ออฟไลน์ได้ตามระบบเดิม
